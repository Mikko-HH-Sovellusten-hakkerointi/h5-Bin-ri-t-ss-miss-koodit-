### Ympäristö

- **Selain:** Firefox 140.13.0esr (64-bit)
- **Virtualisointialusta:** Oracle VirtualBox Version 7.2.16

## Lab0.zip

Avasin Lab0-ohjelman GDB:ssä ja tutkin lähdekoodia komennolla ```list```. Komento näytti vain osan lähdekoodista, joten käytin komentoa ```list 1, 20```, joka tulostaa rivit 1-20. Tämän avulla sain näkyviin koko ohjelman lähdekoodin: 

```bash
1 #include <stdio.h>
2	
3	void buggy_function(int *arr, int size) {
4	    for (int i = 0; i <= size; i++) { // Huomaa: <= aiheuttaa puskuriylivuodon
5	        printf("Element %d: %d\n", i, arr[i]);
6	    }
7	}
8	
9	int main() {
10	    int numbers[] = {1, 2, 3, 4, 5};
11	    buggy_function(numbers, 5); // Virheellinen koko
12	    return 0;
13	}
```

Tämän jälkeen asetin breakpointin riville 4 komennolla ```break 4```. Valitsin rivin 4, koska siinä alkaa taulukkoa käsittelevä silmukka, ja koodissa oleva kommentti viittasi myös siihen, että silmukassa on puskuriylivuodon aiheuttava virhe. 
Halusin myös tarkastella, miten silmukan laskuri i käyttäytyy suorituksen aikana ja selvittää, käykö silmukka taulukon rajojen ulkopuolella. Tämän jälkeen käynnistin ohjelman komennolla ```run```. Eli tässä tapauksessa suoritetaan ohjelmaa normaalisti siihen asti, kunnes se saapuu riville 4 eli juuri ennen silmukkaa.

Tämän jälkeen asetetaan watchpoint komennolla ```watch i```, koska haluan seurata i-muuttujan arvoa. Tätä ei yrityksistä huolimatta voitu tehdä heti ohjelman alussa, koska i on paikallinen muuttuja silmukan sisällä eikä ollut vielä olemassa ennen kuin ohjelma tuli kyseiseen funktioon.
Sitten jatketaan komennolla ```continue```, joka sallii ohjelman jatkaa suorittamista. Kokeilin continue-komentoa mahdollisimman kauan:

Eli koodissa virhe on silmukan ehdossa ```i <= size```. Koska size on 5, silmukka suoritetaan myös arvolla i = 5. Taulukon sallitut indeksit ovat kuitenkin vain 0-4, joten ohjelma yrittää lukea alkiota ```arr[5]```, joka on taulukon rajojen ulkopuolella. 
Tämä voidaan yksinkertaisesti korjata muuttamalla ehto muotoon ```i < size```, jolloin silmukka käy läpi vain taulukon sallitut indeksit eikä suoritu virheellisesti arvolla i = 5.
