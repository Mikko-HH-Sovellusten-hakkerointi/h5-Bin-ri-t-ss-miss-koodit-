## Lab0.zip

Tämän tehtävän tavoitteena on etsiä ohjelman lähdekoodista virhe ja pyritään korjaamaan se.

Avasin Lab0-ohjelman GDB:ssä ja tutkin lähdekoodia komennolla ```list```. Komento näytti vain osan lähdekoodista, joten käytin komentoa ```list 1, 20```, joka tulostaa rivit 1-20. Tämän avulla sain näkyviin koko ohjelman lähdekoodin: 

```bash
1 #include <stdio.h>
2	
3	void buggy_function(int *arr, int size) {
4	    for (int i = 0; i <= size; i++) { // Huomaa: <= aiheuttaa puskuriylivuodon
5	        printf("Element %d: %d\n", i, arr[i]);
6	    }
7	}
8	
9	int main() {
10	    int numbers[] = {1, 2, 3, 4, 5};
11	    buggy_function(numbers, 5); // Virheellinen koko
12	    return 0;
13	}
```

Seuraavaksi asetin breakpointin riville 4 komennolla ```break 4```. Valitsin rivin 4, koska siinä alkaa taulukkoa käsittelevä silmukka, ja koodissa oleva kommentti viittasi myös siihen, että silmukassa on puskuriylivuodon aiheuttava virhe. 
Halusin myös tarkastella, miten silmukan laskuri i käyttäytyy suorituksen aikana. Tämän jälkeen käynnistin ohjelman komennolla ```run```. Eli tässä tapauksessa suoritetaan ohjelmaa normaalisti siihen asti, kunnes se saapuu riville 4 - eli juuri ennen silmukkaa.

Avaan GDB:n ja listaan mahdollisuuksien mukaan koko lähdekoodin näkyville:

```bash
1	#include "stdio.h"
2	
3	void print_scrambled(char *message)
4	{
5	  register int i = 3;
6	  do {
7	    printf("%c", (*message)+i);
8	  } while (*++message);
9	  printf("\n");
10	}
11	
12	int main()
13	{
14	  char * bad_message = NULL;
15	  char * good_message = "Hello, world.";
16	
17	  print_scrambled(good_message);
18	  print_scrambled(bad_message);
19	}
20	
```

Päätin seuraavaksi ajaa ohjelman GDB kautta sellaisenaan ```run```-komennolla. Heti kävi ilmi, että rivillä 7 oleva virhe kaataa ohjelman. Tavallinen konsoli kertoo vain ohjelman kaatuneen segmentation fault -virheeseen, mutta GDB antaa tarkempaa tietoa virheen sijainnista ja syystä:

<p align="center">
<img width="636" height="165" alt="image" src="https://github.com/user-attachments/assets/dac50769-14f1-4847-b558-0ad82e500630" />
  <br>
</p>
<br>

Eli ohjelma yritti käyttää muistia, jota sillä ei ole lupa käyttää. Tulosteesta näkee, että ```message```-muuttujan arvo oli ```0x0```, eli ```NULL```. ```print_scrambled()```-funktio yritti lukea tämän osoittimen kautta muistia lausekkeessa ```(*message)```, mikä aiheutti SIGSEGV-virheen. Virheen syynä oli siis NULL-osoittimen käyttäminen (Rajpurohit 2025). GDB:n käyttö alkaa tässä kohdin tuntua paljon järkevämmältä ja mielekkäämältä kuin ensimmäisessä tehtävässä. 

Teen tähän eräänlaisen tuplakorjauksen nanolla. Lisään ensin koodiin tarkistuksen ```if (message == NULL) return;```, jolloin funktio ei yritä käyttää NULL-osoitinta, jos joku ilkimys joskus sattuisi sellaisen sinne palauttamaan. Lisäksi vaihdan ```bad_message```-muuttujan arvoksi tavallisen merkkijonon ("Up yours, world."), jolloin funktiolle ei enää välitetä NULL-osoitinta. Tämän pitäisi estää ohjelman kaatuminen:

```bash
1	#include "stdio.h"
2	
3	void print_scrambled(char *message)
4	{
5	if (message == NULL)
6		return;
7	
8	  register int i = 3;
9	  do {
10	    printf("%c", (*message)+i);
11	  } while (*++message);
12	  printf("\n");
13	}
14	
15	int main()
16	{
17	  char * bad_message = "Up yours, world.";
18	  char * good_message = "Hello, world.";
19	
20	  print_scrambled(good_message);
21	  print_scrambled(bad_message);
22	}
23	
```

Tässä kohtaa oli pakko käyttää apuna CodingFleetin Assembly to C Converter -työkalua (CodingFleet), sillä vaikka Assembly on tämän kurssin aikana tullut hieman tutuksi, ei sen tulkitseminen ole silti luontevaa. Työkalu toi esille mielenkiintoisen kohdan:

```bash
 for (uint32_t i = 0; i < (uint32_t)length; ++i) {
        /*
         * movsbl sign-extends each byte to int. Casting through
         * signed char reproduces that behavior.
         */
        int first_character = (int)(signed char)first[i];
        int second_character = (int)(signed char)second[i];

        /*
         * Even indexes: add 3.
         * Odd indexes: subtract 7.
         */
        if ((i & 1u) != 0) {
            first_character -= 7;
        } else {
            first_character += 3;
        }

        if (first_character != second_character) {
            return -1;
        }
    }
```

Eli funktion logiikka muokkaa merkkijonoa siten, että parillisissa kohdissa merkin ASCII-arvoon lisätään 3 (0x0000555555555299 <+63>:	add    $0x3,%edx) ja parittomissa kohdissa vähennetään 7 (0x0000555555555294 <+58>:	sub    $0x7,%edx). Koska kyse on jälleen C-kielestä, indeksi aloitetaan nollasta, joka lasketaan parilliseksi luvuksi. Aiemmissa tehtävissä olin käyttänyt lähinnä komentoja list, break, run, watch ja continue, joten ehkäpä suurin uusi debuggerista oppimani asia oli se, että GDB:tä voidaan käyttää myös ilman lähdekoodia ohjelman tutkimiseen.
