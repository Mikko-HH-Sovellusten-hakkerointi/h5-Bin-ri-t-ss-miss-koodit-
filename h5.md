## Lab0.zip

Tämän tehtävän tavoitteena on etsiä ohjelman lähdekoodista virhe ja pyritään korjaamaan se.

Avasin Lab0-ohjelman GDB:ssä ja tutkin lähdekoodia komennolla ```list```. Komento näytti vain osan lähdekoodista, joten käytin komentoa ```list 1, 20```, joka tulostaa rivit 1-20. Tämän avulla sain näkyviin koko ohjelman lähdekoodin: 

```bash
1 #include <stdio.h>
2	
3	void buggy_function(int *arr, int size) {
4	    for (int i = 0; i <= size; i++) { // Huomaa: <= aiheuttaa puskuriylivuodon
5	        printf("Element %d: %d\n", i, arr[i]);
6	    }
7	}
8	
9	int main() {
10	    int numbers[] = {1, 2, 3, 4, 5};
11	    buggy_function(numbers, 5); // Virheellinen koko
12	    return 0;
13	}
```

Seuraavaksi asetin breakpointin riville 4 komennolla ```break 4```. Valitsin rivin 4, koska siinä alkaa taulukkoa käsittelevä silmukka, ja koodissa oleva kommentti viittasi myös siihen, että silmukassa on puskuriylivuodon aiheuttava virhe. 
Halusin myös tarkastella, miten silmukan laskuri i käyttäytyy suorituksen aikana. Tämän jälkeen käynnistin ohjelman komennolla ```run```. Eli tässä tapauksessa suoritetaan ohjelmaa normaalisti siihen asti, kunnes se saapuu riville 4 - eli juuri ennen silmukkaa.

Eli koodissa virhe on silmukan ehdossa ```i <= size```. Koska size on 5, silmukka suoritetaan myös arvolla i = 5. Taulukon sallitut indeksit ovat kuitenkin vain 0-4, joten ohjelma yrittää lukea alkiota ```arr[5]```, joka on taulukon rajojen ulkopuolella. 
Tämä voidaan yksinkertaisesti korjata muuttamalla ehto muotoon ```i < size```, jolloin silmukka käy läpi vain taulukon sallitut indeksit eikä suoritu virheellisesti arvolla i = 5. Korjataan vielä tuo virhe nanon avulla ja suoritetaan ohjelma testiksi:

Avaan GDB:n ja listaan mahdollisuuksien mukaan koko lähdekoodin näkyville:

```bash
1	#include "stdio.h"
2	
3	void print_scrambled(char *message)
4	{
5	  register int i = 3;
6	  do {
7	    printf("%c", (*message)+i);
8	  } while (*++message);
9	  printf("\n");
10	}
11	
12	int main()
13	{
14	  char * bad_message = NULL;
15	  char * good_message = "Hello, world.";
16	
17	  print_scrambled(good_message);
18	  print_scrambled(bad_message);
19	}
20	
```

Päätin seuraavaksi ajaa ohjelman sellaisenaan ```run```-komennolla. Heti kävi ilmi, että rivillä 7 oleva virhe kaataa ohjelman. Tavallinen konsoli kertoo vain ohjelman kaatuneen segmentation fault -virheeseen, mutta GDB antaa tarkempaa tietoa virheen sijainnista ja syystä:
